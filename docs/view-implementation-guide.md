
# View Implementation Guide

This guide explains how to implement a custom [View](/components/app/View.go) for a Gooey
App. It is the frontend half of the [Reactive MVC Architecture](/docs/ARCHITECTURE.md) and
focuses on the `View` layer only. The companion guides are:

- [component-implementation-guide.md](/docs/component-implementation-guide.md)
- [controller-implementation-guide.md](/docs/controller-implementation-guide.md)
- [backend-implementation-guide.md](/docs/backend-implementation-guide.md)

**IMPORTANT**: Before reading this guide, read the [ERRATA.md](/docs/ERRATA.md) document.
It documents the quirks of running Go in a Web Browser and is relevant even for experienced
Go developers.

## Where a View sits in the Loop

Gooey uses a circular, unidirectional flow of data. The View is the outermost layer:

```text
Controller ──action──▶ Backend
    ▲                     │
  event                update
    │                     ▼
  View ◀──render──── Model / Storage
```

Concretely, one iteration looks like this:

1. A user interacts with the DOM rendered by a View (for example clicks a `Button`).
2. The component fires an event (`action`, `change-value`, `change-field`, ...).
3. The [Controller](/components/interfaces/Controller.go) reacts to that event and calls
   an `actions` function that talks to the Backend.
4. The Backend responds with an `update` (for example a shared Schema).
5. The Controller writes the Schema into the [Storage](/components/app/Storage.go) (the model).
6. The Controller calls `View.Render()`, which re-renders the changed components.

A View **must not**:

- perform network requests (`fetch`) itself,
- validate or mutate application state,
- know about the Backend, Schema, or Storage.

A View **must**:

- render the state that the Controller gives it,
- expose a stable `data-*` markup contract so the Controller can find components and
  interpret events.

## Recommended App File Layout

The following layout is the recommended structure for the WebASM frontend of a Gooey App.
The application code lives in `/app`, the static assets it owns live in `/public` (or the
folder that your Backend embeds and serves).

```text
app/
├── go.mod
├── go.sum
├── main.go                      # composition root (app.NewMain)
├── actions/                     # one file per Backend endpoint (Client calls)
│   ├── GetTasks.go
│   ├── CreateTask.go
│   ├── UpdateTask.go
│   └── DeleteTask.go
├── components/                  # app-specific Component implementations
│   ├── RegisterTo.go
│   └── CustomComponent.go
├── controllers/                 # one Controller per View
│   ├── RegisterTo.go
│   ├── Tasks.go
│   └── Settings.go
├── structs/                     # app-local helper types (queues, schedulers, ...)
│   └── ...
├── views/                       # one custom View per non-default View
│   ├── RegisterTo.go
│   └── Settings.go
└── public/                      # served (and usually go:embed-ed) static assets
    ├── index.html
    ├── settings.html
    ├── app/
    │   ├── index.css
    │   ├── components/
    │   │   └── CustomComponent.css
    │   └── views/
    │       └── Settings.css
    ├── design/                  # copy of the Gooey App theme
    ├── wasm_exec.js             # generated by the Go WebASM toolchain
    └── wasm_init.js
```

The package responsibilities are:

| Folder        | Responsibility                                                          |
|:--------------|:------------------------------------------------------------------------|
| `main.go`     | Wires everything together. Registers components, controllers, views.    |
| `actions`     | Thin functions around [app.Client](/components/app/Client.go). No UI.   |
| `components`  | Custom `interfaces.Component` implementations.                          |
| `controllers` | One Controller per View. Binds events, runs actions, renders.           |
| `structs`     | App-local helper types that are not Schemas and not Components.         |
| `views`       | Custom `interfaces.View` implementations.                               |
| `public`      | HTML, CSS and WebASM assets served by the Backend.                      |

Every file inside `app/views` and `app/components` that uses DOM bindings must start with
the `//go:build wasm` build tag, because it compiles only for the `js/wasm` platform.

## The View Contract

A View implements [interfaces.View](/components/interfaces/View.go). Because that interface
embeds every method of [interfaces.Component](/components/interfaces/Component.go), a View
is also a Component and can be used anywhere a Component is expected.

| Method                     | Purpose                                                                 |
|:---------------------------|:------------------------------------------------------------------------|
| `Name() string`            | Lowercase identifier, matches `data-name`.                             |
| `Label() string`           | Human readable label, used by the header/aside navigation.             |
| `Path() string`            | Navigate target, matches `data-path` (for multi-page apps).            |
| `Enable() bool`            | Enables the interactive parts of the View.                             |
| `Disable() bool`           | Disables the interactive parts of the View.                            |
| `Mount() bool`             | Reads attributes and maps child elements to Components.                |
| `Unmount() bool`           | Unmaps and unmounts child Components.                                  |
| `Enter() bool`             | Sets `data-state="active"` when the View becomes the active View.      |
| `Leave() bool`             | Removes `data-state` when another View becomes active.                 |
| `Query(string) Component`  | Finds a nested Component by CSS-like selector.                         |
| `Render() *dom.Element`    | Re-renders the View and its child Components.                          |
| `String() string`          | Serializes the View (used for server-side rendering).                  |

`app.Main` calls `Mount()`/`Unmount()` while building/tearing down the Component graph, and
calls `Enter()`/`Leave()` from [app.Main.ChangeView](/components/app/Main.go) together with
the matching Controller's `Enter()`/`Leave()`. You usually do not call these yourself.

## The Markup Contract

A View maps to exactly one `<section>` element inside `<main>`. The section attributes are
read by `Mount()` and written back by `Render()`:

```html
<main data-view="settings">
	<section data-name="settings" data-label="Settings" data-path="/settings.html">
		<article>
			<h3 data-type="settings">Settings</h3>
			<fieldset data-name="settings">(...)</fieldset>
		</article>
	</section>
</main>
```

- `data-name` identifies the View and is used for `main.RegisterView`/`main.RegisterController`
  Lookups (both are lowercased).
- `data-label` is shown in the [Header](/components/layout/Header.go) or
  [Aside](/components/layout/Aside.go) navigation.
- `data-path` is the navigation target of that navigation entry.
- `data-layout` is optional and maps to [types.Layout](/components/types/Layout.go).

The child markup is written entirely with `data-*` attributes, following the rules in
[ARCHITECTURE.md](/docs/ARCHITECTURE.md):

- Use `data-action` for elements that trigger events.
- Use `data-layout` for layout components (`grid`, `flex`, `flow`).
- Use `data-state` for activity/visibility (`active`).

## Implementing a Custom View

The following walkthrough implements the `Settings` View from the
[app-views example](/examples/components/app-views/views/Settings.go). Start with the struct
and the two constructors.

### 1. Struct and Constructors

```go
//go:build wasm

package views

import "github.com/cookiengineer/gooey/bindings/dom"
import "github.com/cookiengineer/gooey/components/content"
import "github.com/cookiengineer/gooey/components/layout"
import "github.com/cookiengineer/gooey/components/utils"
import "github.com/cookiengineer/gooey/components/interfaces"
import "github.com/cookiengineer/gooey/components/types"
import "sort"
import "strings"

type Settings struct {
	Element *dom.Element           `json:"element"`
	Layout  types.Layout           `json:"layout"`
	Content []interfaces.Component `json:"content"`
	name    string
	label   string
	path    string
}

func ToSettings(element *dom.Element) *Settings {

	var view Settings

	view.Element = element
	view.Layout  = types.LayoutFlow
	view.Content = make([]interfaces.Component, 0)

	view.name  = strings.ToLower(element.GetAttribute("data-name"))
	view.label = element.GetAttribute("data-label")
	view.path  = strings.ToLower(element.GetAttribute("data-path"))

	return &view

}
```

`ToSettings` is the only constructor the framework needs. It is registered in step 7 and is
called by `app.Main` for the `<section data-name="settings">` element. A `NewSettings(name,
label, path)` constructor is optional and only useful when you build a View entirely from
code instead of from existing markup.

### 2. Mount: Reading Attributes and Mapping Children

`Mount()` is called once, after the Component graph has been parsed by
[components.Document](/components/Document.go). It is a top-down call tree: each Component
is responsible for mounting its own nested Components.

**IMPORTANT**: In Gooey >= `0.0.6` the `To*` constructors no longer mount automatically.
`Mount()` must be called explicitly by the parent, and custom Views must map their own
children. The default [app.View.Mount](/components/app/View.go) only iterates
`view.Content`, because `app.Main` populates the content of *default* Views through
`Document.CreateComponent`. A *custom* View is responsible for building its own `Content`.

```go
func (view *Settings) Mount() bool {

	if view.Element != nil {

		tmp_name := view.Element.GetAttribute("data-name")
		if tmp_name != "" {
			view.name = strings.ToLower(tmp_name)
		}

		tmp_label := view.Element.GetAttribute("data-label")
		if tmp_label != "" {
			view.label = tmp_label
		}

		tmp_layout := view.Element.GetAttribute("data-layout")
		if tmp_layout != "" {
			view.Layout = types.Layout(tmp_layout)
		}

		tmp_path := view.Element.GetAttribute("data-path")
		if tmp_path != "" {
			view.path = strings.ToLower(tmp_path)
		}

		elements   := view.Element.Children()
		components := make([]interfaces.Component, 0)

		for _, element := range elements {

			if element.TagName == "ARTICLE" {
				components = append(components, layout.ToArticle(element))
			} else if element.TagName == "TABLE" {
				components = append(components, content.ToTable(element))
			}

		}

		view.Content = components

		for _, component := range view.Content {
			component.Mount()
		}

		return true

	} else {
		return false
	}

}
```

Map every element that has a matching Gooey Component (`ARTICLE`, `TABLE`, `FIELDSET`,
`FIGURE`, `BUTTON`, `INPUT`, ...) to its `To*` constructor. Wrap plain elements in
[components.NewComponent](/components/Component.go). If you have registered an app-specific
Component (see the [app-components example](/examples/components/app-components)), map it here
as well.

### 3. Unmount

`Unmount()` is the mirror image of `Mount()`. Always unmount your child Components and remove
any DOM event listeners that were attached outside of the `Component` abstraction.

```go
func (view *Settings) Unmount() bool {

	for _, component := range view.Content {
		component.Unmount()
	}

	return true

}
```

### 4. Enter and Leave

`Enter()` and `Leave()` toggle the visual activity state. `app.Main.ChangeView` calls them
automatically when the user switches Views, so they should stay cheap and idempotent.

```go
func (view *Settings) Enter() bool {

	if view.Element != nil {
		view.Element.SetAttribute("data-state", "active")
	}

	return true

}

func (view *Settings) Leave() bool {

	if view.Element != nil {
		view.Element.RemoveAttribute("data-state")
	}

	return true

}
```

### 5. Query: Finding Nested Components

`Query()` uses CSS-like selectors. The first selector is matched against the View's own
`<section>` element, which means **the query is self-including**. A Controller can therefore
write `controller.View.Query("section > article > table")` and does not need to prepend
anything.

`Query()` returns [interfaces.Component](/components/interfaces/Component.go) instead of a
concrete type, because [interfaces.View](/components/interfaces/View.go) and
[interfaces.Component](/components/interfaces/Component.go) reference each other. This is why
the framework provides the `Wrap`/`Unwrap` helpers (see step 6).

```go
func (view *Settings) Query(query string) interfaces.Component {

	selectors := utils.SplitQuery(query)

	if len(selectors) >= 2 {

		if view.Element != nil {

			if utils.MatchesQuery(view.Element, selectors[0]) == true {

				tmp_query := utils.JoinQuery(selectors[1:])

				for _, content := range view.Content {

					tmp_component := content.Query(tmp_query)

					if tmp_component != nil {
						return tmp_component
					}

				}

			}

		}

	} else if len(selectors) == 1 {

		if view.Element != nil {

			if utils.MatchesQuery(view.Element, selectors[0]) == true {
				return view
			}

		}

	}

	return nil

}
```

`QuerySelector()` and `QuerySelectorAll()` are optional convenience methods that delegate to
the underlying [`*dom.Element`](/bindings/dom). They are not part of `interfaces.View`, but are
handy when you need raw DOM nodes without wrapping them in a Component.

### 6. Wrap and Unwrap

Because `Query()` returns an interface, the caller uses the generic helpers to get the concrete
instance back. This replaces the verbose native type assertion:

```go
// Verbose, and repeated everywhere:
component := controller.View.Query("section > article > table")
table, ok := component.(*content.Table)

// Idiomatic Gooey:
table, ok := components.UnwrapComponent[*content.Table](
	controller.View.Query("section > article > table"),
)
```

The helpers are:

- [components.UnwrapComponent](/components/UnwrapComponent.go) for Components.
- [components.WrapComponent](/components/WrapComponent.go) to register a `To*` constructor.
- [app.UnwrapView](/components/app/UnwrapView.go) / [app.WrapView](/components/app/WrapView.go)
  for Views.
- [app.UnwrapController](/components/app/UnwrapController.go) /
  [app.WrapController](/components/app/WrapController.go) for Controllers.

### 7. Render and String

`Render()` writes the current state back into the DOM. It must always sync the `data-*`
attributes and then replace the children with the rendered child Components.

```go
func (view *Settings) Render() *dom.Element {

	if view.Element != nil {

		if view.name != "" {
			view.Element.SetAttribute("data-name", view.name)
		}

		if view.label != "" {
			view.Element.SetAttribute("data-label", view.label)
		}

		if view.path != "" {
			view.Element.SetAttribute("data-path", view.path)
		}

		if view.Layout != types.LayoutFlow {
			view.Element.SetAttribute("data-layout", view.Layout.String())
		}

		elements := make([]*dom.Element, 0)

		for _, component := range view.Content {
			elements = append(elements, component.Render())
		}

		view.Element.ReplaceChildren(elements)

		return view.Element

	}

	return nil

}
```

`String()` serializes the View and its Components. It is used for server-side rendering and
does not need to match the browser DOM one-to-one, but it should produce semantically
equivalent markup.

### 8. Register the View

Register the View constructor with `app.Main` from a `RegisterTo` function so that
`main.go` stays declarative:

```go
package views

import "github.com/cookiengineer/gooey/bindings/dom"
import "github.com/cookiengineer/gooey/components/app"
import "github.com/cookiengineer/gooey/components/interfaces"

func RegisterTo(main *app.Main) {

	main.RegisterView("settings", func(element *dom.Element) interfaces.View {
		return ToSettings(element)
	})

}
```

`app.WrapView` is the generic shorthand for exactly this closure:

```go
func RegisterTo(main *app.Main) {
	main.RegisterView("settings", app.WrapView(ToSettings))
}
```

**IMPORTANT**: `RegisterView` lowercases the name, and `app.Main` looks up the constructor by
the `data-name` of the `<section>`. Keep the registered name, `data-name`, and the
`main.RegisterController` name identical. The name is also used to pair the View with its
Controller.

## View Checklist

- [ ] File has the `//go:build wasm` build tag.
- [ ] Package is `views` and the file is named after the feature (`Settings.go`).
- [ ] `ToSettings(*dom.Element)` reads `data-name`, `data-label`, `data-path`, `data-layout`.
- [ ] `Mount()` maps every child Component and calls `Component.Mount()` on each.
- [ ] `Unmount()` unmounts every child Component and removes DOM listeners.
- [ ] `Enter()`/`Leave()` only toggle `data-state="active"`.
- [ ] `Query()` recurses into `Content` and is self-including.
- [ ] `Render()` re-applies `data-*` attributes and replaces children.
- [ ] `String()` produces equivalent markup.
- [ ] The View is registered in `views/RegisterTo.go` with the same name as its Controller.
- [ ] App-owned CSS lives in `public/app/views/<Name>.css`.
